# 테스트 프로세스 — 베타 37명 (헬로마이미 동아리 부원)
기준: 전략기획안 v2.7 / 작성 2026-07-12 / **개정 v2: VoIP 우선 (2026-07-12)**

> ## 개정 v2 (창업자 결정): 테스트도 VoIP로 진행 — PSTN(Vapi) 폐기
>
> 진짜 전화(PSTN) WoZ 대신 **처음부터 제품과 같은 VoIP 스택**(LiveKit + 캐스케이드)으로 테스트한다.
>
> **바뀌는 것**
> - R1의 "전화 발신" → **알림톡/문자로 통화 링크 발송** ("보라가 기다리고 있어요 📞") → 탭 → 브라우저에서 통화. Vapi 계정·발신번호가 필요 없어지고, 대신 통화 페이지+음성 에이전트 개발이 W0–1에 선행된다.
> - 응답률의 정의가 "전화 받기"에서 **"링크 탭 후 통화 시작"**으로 바뀐다. 링크 탭이 전화 받기보다 마찰이 크므로 게이트를 75% → **70%**로 조정 (지인 보정은 유지).
> - **잠금화면 수신 트리거 검증은 R3(CallKit)로 이월** — "정해진 시간에 걸려오는 전화의 힘"은 이 단계에서 완전히 측정되지 않음을 인지하고 판정한다.
> - 기존 R1(WoZ)과 R2(웹 베타)가 사실상 합쳐진다 — 일기 파이프라인도 첫날부터 자동(운영자는 검수만).
>
> **얻는 것**: 광대역 음질(전사 품질↑), 테스트 코드가 곧 제품 코드, 발신번호·스팸 인식 문제 소멸, 원가 구조가 제품과 동일(분당 ~45원).
>
> **개정 일정 (약 7주)**: W0–1 개발+준비(동의서·설문 병행) → W2–4 R1: 웹 VoIP 베타 3주 (37명, 기억 콜백 A/B 포함) → W5–6 R3: TestFlight CallKit (아이폰 보유자, 잠금화면 수신 검증 + 팀 도그푸딩) → W7 종합 판정.
> 아래 본문의 운영 루틴·게이트·측정 시트는 "발신"을 "링크 발송"으로 읽으면 그대로 유효하다.


## 0. 코호트 특성과 판정 보정 (먼저 읽을 것)

**참가자**: 헬로마이미 동아리 부원 37명 (기획서의 WoZ 표본 30–50명 범위 내).

**⚠️ 지인 코호트 편향**: 동아리 부원은 운영자와 친분이 있어 ① 전화를 의리로 받고 ② 불만을 말하지 않는 방향으로 결과가 부풀려진다. 따라서:

1. **게이트 기준을 상향 적용한다** — 비지인 기준 60%가 아니라 **75%**. 지인인데도 75%를 못 넘으면 명백한 실패 신호다.
2. **이 코호트로 확정할 수 있는 것과 없는 것을 구분한다**:
   - 확정 가능: 대화·일기 품질, 페르소나 선호, 루프의 작동, 버그, 위기 프로토콜, "계속 쓰고 싶은가"의 질적 신호
   - 확정 불가: 시장 응답률·리텐션의 절대값 → **정식 판정(Week 12 게이트)은 이후 비지인 코호트에서 다시 잰다**
3. 행동 지표(통화 길이, 발화 비중, 일기 열람까지의 시간)는 의리로 조작이 어려우므로 **말보다 행동 지표를 믿는다.**

## 2. W0 — 준비 주

### 2-1. 참가 동의 (필수 서면/전자 동의)
- 통화가 **녹음·전사되어 저장**된다는 것, 열람 범위(본인+운영진 최소인원)
- 음성 처리에 해외 API가 사용됨(국외 이전 고지)
- 언제든 중도 이탈 가능, 개별 통화 삭제·전체 삭제 요청 가능
- 이 서비스는 상담·치료가 아니며, 위기 신호 시 109 안내가 나감
- 사례비: 2주 완주 시 기프티콘 1만 원 + 심층 인터뷰 응답 시 5천 원 추가 (권장 — 의리 참여가 아니라 계약 참여로 만들어 편향을 줄이는 효과도 있다)

### 2-2. 사전 설문 (5분)
- 기기(아이폰/갤럭시 — R3 배정용), 학년/전공, 일기 시도·실패 경험, 원하는 통화 시간대
- **페르소나 선택**: 보라(반말 친구)/무주(담담한 기록자)/해나(다정한 코치) 3종 인사말 샘플 듣고 선택 → 선택 분포 자체가 첫 데이터. 목표 균형(약 13/12/12)에서 크게 쏠리면 그것도 발견이다
- "이 번호로 전화가 갑니다" 안내 + 번호 저장 (스팸 인지 통제)

### 2-3. 인프라 세팅 (운영자)
- Vapi/Retell 계정 + 페르소나 3종 통화 스크립트 (체크인→메인 질문 1개→반영→랩업, 5분 캡)
- TTS 2종 × 페르소나 매칭 (주차별 스왑으로 블라인드 A/B — W1은 A목소리, W2는 B목소리)
- **일기 전달 파이프라인 (반자동)**: 통화 종료 웹훅 → 전사 → LLM 일기+미러링 생성 → 운영자 검수(첫 2주 전수 QA — 바넘 게이트 수동 적용) → **링크로 카톡 발송** (통화 종료 10분 내)
  - 일기는 카톡 텍스트가 아니라 **헬로마이미 숨은 웹페이지 링크**로 보낸다 → 열람 여부·열람까지의 시간이 정확히 측정되고, R2의 기반 코드가 미리 만들어진다
- 측정 시트 (아래 5장 스키마)
- **위기 대응 준비**: 운영자가 매일 전사를 검토, 위기 신호 발견 시 24시간 내 개별 연락 + 109 안내 스크립트. 대응 담당자 1인 지정

## 3. 라운드별 프로세스

### R1 (W1–2): WoZ 전화 테스트 — "받는가, 말하는가, 열어보는가"

**일일 운영 루틴** (운영자, 1일 ~1.5시간):
1. 저녁: 스케줄된 발신 확인 (참가자별 지정 시간, 무응답 시 5분 후 1회 재시도)
2. 통화 후: 일기 생성 → 검수 → 10분 내 링크 발송
3. 밤: 측정 시트 기록 + 전사 위기 스크리닝
4. 주 1회: 참가자 단체방에 운영 공지 (독촉·죄책감 카피 금지 — "안 받아도 괜찮아요"가 공식 톤)

**R1 게이트 (지인 보정 적용)**:
| 지표 | 통과 기준 | 의미 |
|---|---|---|
| 응답률 (재시도 포함) | **75%+** | 비지인 60% 기준의 지인 보정치 |
| 평균 통화 길이 | 3분+ | 받기만 하고 안 말하면 실패 |
| 사용자 발화 비중 | 60%+ | "나와의 대화" 성립 여부 |
| 일기 링크 열람률 | 75%+ | 산출물에 가치를 느끼는가 |
| 열람까지 중앙값 | 2시간 내 | 궁금해서 여는가, 의무로 여는가 |
| 14일 차 잔존 (계속 받는 사람) | 70%+ | 2주 감쇠 곡선 |

**질적 킬 신호** (숫자가 통과해도 3명 이상에게서 나오면 경보): "부담스러웠다", "안 받으면 미안했다"(죄책감 설계 실패), "일기가 내 말 같지 않다"(대필 감지), "미러링이 소름·점쟁이 같다"(바넘 경보).

### W3: 분석 + 심층 인터뷰
- 인터뷰 8–10명 구성: 헤비 3 + 중간 3 + 이탈/저조 3 (**이탈자 인터뷰가 가장 값지다**)
- 핵심 질문: 어떤 날 받기 싫었나 / 일기에서 어디를 다시 읽었나 / 돈 얘기는 하지 않는다(v2.5 — 수익화 후순위)
- 판정 회의: R1 게이트 → R2 진행/중단/수정 재실험

### R2 (W4–6): 웹 통화 베타 — "대화와 루프가 좋은가"
- 헬로마이미 `/call/lab` (숨은 라우트, 초대 계정만): 푸시/알림톡 → 링크 탭 → 브라우저 통화 → 이번엔 **자동 파이프라인**으로 일기 생성 (운영자는 검수만)
- 신규 검증: 미러링 어색률(수동 QA 20% 미만), 주간 요약 열람, **기억 콜백 A/B** (참가자 반씩 on/off — 응답률·통화 길이 델타 측정, 자기발견 레이어의 첫 정량 근거)
- R2 게이트: 대화 품질 만족(주간 설문 4점/5점+), 미러링 어색률 <20%, 콜백 델타 양수, 3주 잔존 60%+

### R3 (W7–8): TestFlight — "잠금화면에서 울리는가"
- 헬로마이미 iOS 셸 포크 + CallKit Capacitor 플러그인, 아이폰 보유자만
- 검증: **수신 성공률 98%+** (스케줄 발신 대비 실제 벨 울림 — 이 숫자가 이 라운드의 전부), WebView 통화 오디오 품질(끊김·에코 불만 0), 지연 1.5초 실측
- **팀 도그푸딩 병행**: 팀 전원이 2주간 매일 자기 전화를 실제로 받는다. 만든 사람이 전화를 피하기 시작하면 그게 가장 정직한 데이터다
- 갤럭시 참가자는 R2(웹)를 계속 사용 → 안드로이드 수요·웹 폴백 만족도 데이터로 활용

### W9: 종합 판정
- R1·R2·R3 게이트 전부 통과 → 본 탑재(정원제 베타, 기능 플래그) 착수
- 부분 통과 → 실패 지표별 대응: 응답률 실패=시간대·페르소나 피벗 / 품질 실패=대화 엔진 수정 후 R2 재실행 / 수신 신뢰성 실패=네이티브 오디오 경로 승격
- **이 코호트 통과 ≠ 시장 검증**: 본 탑재 후 첫 비지인 코호트(헬로마이미 일반 유저)에서 비보정 게이트(응답률 55%, D14 35%)를 다시 잰다

| 역할 | 담당 | 주당 시간 |
