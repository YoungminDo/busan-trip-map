## 1. 개요 & 핵심 원칙

**한 줄 정의:** 이름·얼굴이 아니라 **회사·직무 적합도**로 연결되는, 텍스트 기반 커리어 커피챗.

**핵심 UX 원칙**
- 학생은 **고민 → 질문 → 신뢰 지표 → 커피콩(정중한 연결)** 순으로 이동한다.
- 학생 판단 순서(카드/상세 정보 우선순위와 일치):
  1. **관련성** — “내 회사·직무 맞아?” (회사·직무명·연차)
  2. **적합도** — “내 고민 풀어줄 사람?” (이런 고민을 도와드려요 · 추천 대상)
  3. **신뢰** — “진짜 현직자? 믿을만?” (검증 · 경력 · 후기)
  4. **응답 확신** — “답 올까? 언제?” (응답시간 · 질문수 · 무응답 환불)
  5. **비용 납득** — “990원?” (커피콩 = 가격 아닌 명분)
  6. **행동** — 커피콩으로 질문 전달
- **이름·얼굴은 보조**(있으면 좋고 없어도 무방). 신뢰는 얼굴이 아니라 **검증**이 만든다.

**금지(안티패턴):** 소개팅앱(얼굴 중심) · 배달앱(속도 경쟁) · 멘토판매(구매·인기 1위) · 사람 점수화(별점·랭킹).

## 2. 정보 아키텍처

**화면 목록 (구현됨)**

| ID | 화면 | 진입 |
|---|---|---|
| `list` | 커피챗 리스트 (무한 피드) | 하단탭 ‘커피챗’ · 기본 화면 |
| `explore` | 탐색/검색 (질문·직무·회사) | 리스트 상단 검색바 탭 |
| `detail` | 코치(파트너) 상세 | 코치 카드 탭 |
| `write` | 질문 작성 | 상세 CTA / 인기질문 탭 |
| `pay` | 결제 (커피콩 전달) | 작성 CTA |
| `done` | 전달 완료 / 답변 대기 | 결제 CTA |
| `home` | 홈 (요약) | 하단탭 ‘홈’ |

**내비게이션 모델**
- 스택 기반. `go(id)` push, `back()` pop, 하단탭은 스택 리셋.
- 하단 탭바 5개: **홈 · 프로그램 · 커피챗 · 채용소식 · 커뮤니티** (프로토타입은 홈/커피챗만 활성).
- 흐름: `list → detail → write → pay → done`. 완료 후 ‘다른 파트너 둘러보기’로 `list` 리셋.

### `Profile` (멀티프로필 항목 = 회사×역할 노출 단위)
| 필드 | 타입 | 설명 |
|---|---|---|
| `company` | string | 회사명 |
| `companyType` | string | 업무영역/산업 |
| `job` | string | 직무영역 |
| `roleName` | string | 직무명/직함(카드 타이틀) |
| `brand` | string? | 담당 브랜드(회사≠브랜드일 때) |
| `logo` | `{text,bg}` | 회사(고용주) 로고 |
| `status` | `'current' \| 'past'` | 재직중 / 전직 |

**회사(고용주) ≠ 브랜드 ≠ 직무명(직함) — 3계층 구분 (중요)**
한 사람의 소속은 세 층위로 나뉜다. 이름/얼굴이 아니라 이 3계층으로 카드를 구성한다.

| 계층 | 필드 | 예시 | 카드에서 |
|---|---|---|---|
| **회사(고용주)** | `company` (+`logo`) | 바이어스도르프(Beiersdorf) | 로고·회사명 = 검증/신뢰의 뿌리 |
| **브랜드(담당 제품)** | `brand` | 니베아 | 서브라인 "담당 브랜드 · 니베아" |
| **직무명(직함/포지션)** | `roleName` | 니베아 브랜드 매니저 | 카드 타이틀 |

- 흔한 오류: 브랜드(니베아)를 회사로 오인 표기. **로고·검증은 고용주(바이어스도르프) 기준**, 브랜드는 담당 제품으로 별도 노출.
- FMCG·유통·엔터에서 특히 잦다(예: 펩시코=회사 / 미린다·마운틴듀=브랜드 / 탄산음료 브랜드 매니저=직함).
- `brand` 는 검색 하이스택에 포함(브랜드명으로도 검색되게), 카드 타이틀 로고·회사명은 항상 `company` 기준.

**핵심 규칙**
- **프로필은 여러 개, 사람은 하나.** 후기·검증·도움%·응답시간은 **Coach 단위로 공유**(프로필마다 0에서 시작하지 않음).
- 카드/검색은 **Profile 단위로 노출**(회사 수만큼 노출 → 히트레이트↑).
- 연차는 **전체 경력(totalYr)** 사용. 회사별 기간은 `career` 타임라인(검증용).

### Enums / 표준값 (실서비스 정규화 필요)
- `job`(직무영역): 마케팅 · 데이터 · UX/UI · 사업개발 · PM/기획 · 영업 · 콘텐츠/미디어 · HR · 금융/전략 …
- `companyType`(업무영역): 스타트업 · 외국계 · 플랫폼 · 대기업 · 글로벌 FMCG · 핀테크 · 헬스케어 …
- `status`: current | past

## 5. 컴포넌트 카탈로그

### 5.1 코치 카드 (`.ccard`)
구성(위→아래):
1. **검증 뱃지** — “✓ 헬로마이미 검증 파트너”
2. **타이틀** — `[로고] 회사 · 직무명 · 총연차 [재직중/전직]`
3. **서브라인(meta)** — `직무영역 · 업무영역` (예: 마케팅 · 글로벌 FMCG)
4. **💬 이런 고민을 도와드려요** — 코치 소개(intro)
5. **추천 태그** (tags)
6. **지표** — `도움됐어요 N% · 질문 N개 · 평균 N시간`
7. **푸터** — `이름 파트너` (+ 멀티프로필이면 `🔗 N개 회사 경력`)

로고 뱃지(`.logo`): 높이 24, 브랜드색 배경, 흰 워드마크, 그림자. 상세에선 30.

### 5.2 추천 블록 (`.reco`) — 인피드 추천
- 연한 배경 카드 + 우상단 **“추천” 태그**(광고 아님 명시).
- 헤더 아이콘+제목, 본문 가로 스크롤 선반 카드(`.scard`).
- 5종: `⚡이번 주 응답 빠른` · `💚이번 주 도움 많은` · `🎯비전공·문과생 추천` · `🌏외국계·글로벌` · `🎓나와 같은 {학교} 선배`
- 선반 카드: 맥락칩(fast/help/rec) + 로고+회사·직무 + 연차 + 이름. **순위 번호 없음**(코치 명예).

### 5.3 요청 카드 (`.reqcard`)
- 점선 카드. “🙋 찾는 회사·직무가 있나요? — ‘○○ 다니는 분’ 요청하면 찾아드려요 · 요청 ›”
- 피드에 삽입 + 검색 무결과/탐색 하단에도 배치. **미충족 수요 신호로 로깅**.

### 5.4 필터바 (`.filters` + `.facetpicker`)
- **정렬(단일선택):** 추천순 · 응답 빠른순 · 도움 많은순
- **패싯(값 선택):** 직무 · 회사유형 · 내 상황 → 탭하면 하단 옵션 picker 노출
- 활성 시 **초기화** 칩 노출.

### 5.5 초성/ABC 인덱스 (`.idxbar`)
- 탐색 ‘직무로/회사로’에서 전체 + ㄱㄴㄷ…/A–Z. 한글 초성 추출(쌍자음→기본자음 병합) + 영문 첫글자.

### 5.6 실시간 인기 검색어 (`.trend`)
- 탐색 ‘질문으로’ 상단. 라이브 펄스닷 + 순위(상위3 강조) + ▲/NEW/▼. **주제 랭킹(사람 아님)**.

### 5.7 신뢰/검증 요소
- 검증 뱃지, 상세 “신뢰 정보”(재직·경력·실명 인증 + 비공개 안내), 경력 타임라인 “검증 완료” 태그.

## 6. 화면별 사양

### 6.1 리스트 (`list`) — 무한 피드
- 상단바: “커피챗” + 커피콩 잔액(`☕ 커피콩 N`)
- 검색바(`질문·직무·회사로 찾아보세요`, 탭→explore) + 활용 가이드
- 필터바 + 패싯 picker
- 섹션: “현직자 커피챗 / 헬로마이미가 직접 검증한 현직자예요. 내 질문에 맞는지 먼저 보세요.”
- **무한 피드**: 코치 카드 스트림 + 인피드 추천 + 요청 카드. 하단 “파트너 더 불러오는 중…”
- 필터/정렬 활성 시 → 필터된 평면 리스트(“N명 · 정렬명”) + 무결과 요청 CTA.

### 6.2 탐색 (`explore`)
- 상단: 뒤로 + 검색 입력(스코프별 placeholder 회전)
- **스코프 3개:** 질문으로 · 직무로 · 회사로
- 빈 상태:
  - 질문으로 → 실시간 인기 검색어 + “이렇게 물어보세요” + 직무칩 + 회사칩
  - 직무로 → 초성 인덱스 + 직무칩 + 요청 CTA
  - 회사로 → 초성 인덱스 + 회사(로고)칩 + 요청 CTA
- 입력 시: **하이브리드 매칭**(회사·직무·역할·태그·질문 + 멀티프로필). 결과 “N개 프로필”. 무결과 → 요청 CTA.

### 6.3 코치 상세 (`detail`)
섹션 순서:
1. 검증 뱃지 + 타이틀(직무명) + 서브라인
2. **💬 이런 고민을 도와드려요** (intro)
3. **신뢰 정보** — ✓재직·경력 인증 / ✓실명 인증(비공개) + 안내문
4. **노출 프로필** (멀티프로필 시) — 회사별 로고·직무명·재직중/전직 + “각각 검색에 노출, 이력·후기·검증 공유” 안내
5. **어떤 파트너예요** (about)
6. **이런 분에게 추천해요** (recWho 불릿)
7. **이런 질문에 잘 답해요** (good) / **이런 질문은 조금 어려워요** (hard)
8. **경력** (career 타임라인 + “헬로마이미 검증 완료” 태그)
9. **답변 스타일** (style)
10. **도움 지표** (도움됐어요% / 받은 질문 / 평균 응답 — statbox)
11. **답변 샘플** (sampleQ/A)
12. **도움 후기** (reviewTags + review + reviewBy)
13. **더 깊게 이야기하고 싶다면** — 비대면 상담(30분) 연계 업셀
- 하단 고정 CTA: **☕ 커피콩으로 질문하기** (커피콩 1개 · 990원)

### 6.4 질문 작성 (`write`)
- **좋은 질문 가이드**(3단계): 내 상황 · 한 가지로 좁히기 · 원하는 방향
- 질문 입력(**1개**), 내 상황(학년·전공·관심직무·고민), **원하는 답변 방식** 태그(현실적/단계별/따뜻하게/짧고 핵심만)
- 좋은 질문 예시. CTA: **질문 미리보고 전달하기**

### 6.5 결제 (`pay`) — 커피콩 전달
- 커피콩 티켓(초록) `☕ 커피콩 1개 · 990원` + “질문이 준비됐어요. 커피콩으로 정중하게 전달할까요?”
- 명분 카피(무료 DM 대비)
- **보내는 질문**(미리보기) + 대상 파트너
- 안전장치: ✓무응답 시 커피콩 환불 · ✓전송 전 수정 · ✓평균 24시간
- CTA: **☕ 커피콩으로 전달하기 · 990원**
- **결제 = 전달 게이트**(답변 열람 아님). 코치는 결제된 질문에만 답변.

### 6.6 완료 (`done`)
- ✓ “커피콩과 함께 질문이 전달되었어요” + 평균 24시간 안내
- 타임라인: 접수 → 전달(대기중) → 작성중 → 도착·알림
- 수정 가능 안내. CTA: 다른 파트너 둘러보기

### 6.7 홈 (`home`)

- **지금 물어볼 수 있는 파트너**(가로 카드) — “얼굴이 아니라 질문 적합도로 골라요”

## 7. 핵심 로직 / 알고리즘 (프로토타입 기준)

> ⚠️ 프로토타입은 **랜덤 셔플**로 ‘무한한 척’ 한다. 실서비스는 §10의 개인화 랭킹으로 대체.

### 7.1 멀티프로필 펼치기
```
profileViews() =
  coaches.flatMap(c => c.profiles ? c.profiles.map(pf => [c, pf]) : [[c, null]])
// 회사 수만큼 카드. 카드 렌더는 viewOf(c, pf)로 프로필별 값 사용, 지표는 c 공유.
```

### 7.2 무한 피드 (배치)
```
1 batch = 프로필뷰 shuffle → 앞 3개 카드 + 추천블록 1개 (+ batchNo 홀수면 요청카드)
scroll 바닥 320px 전 → appendBatch (상한 없음, 무한)
정렬/필터 활성(filtering) 시 → 피드 중단, 필터 리스트로 대체
```

### 7.3 추천 블록 노출 (`recoQueue`)
```
5종을 shuffle해 큐에 적재 → 배치마다 1개 pop → 비면 재shuffle
각 블록 내부: pick()로 조건 코치 정렬 후 상위 4 (fast=응답↑, help=도움%↓, rec/school=조건매칭)
```

### 7.4 필터 엔진
```
state: sortMode('rec'|'fast'|'help'), facet{job,comp,sit}
computeFiltered():
  coaches
   .filter(job)  = (job+role+tags).includes(선택값)
   .filter(comp) = (companyType+meta).includes(선택값)
   .filter(sit)  = (rec+tags+meta).includes(선택값)
   .sort(fast=응답↑ / help=도움%↓ / rec=원순서)
applyFeed(): rec+무패싯 → 무한피드 / 그 외 → 필터 평면 리스트
```

### 7.5 검색 (하이브리드)
```
profileViews를 대상으로, viewOf값(회사·업무영역·직무영역) + role·meta·질문·태그를 haystack에
쿼리 토큰 중 하나라도 포함되면 hit → 프로필 카드로 표시
"펩시코"(엔티티) / "비전공 데이터"(의도) 모두 매칭
```

### 7.6 초성 인덱스
```
initialOf(str): 한글 음절 → 초성(쌍자음→기본), 영문 → 대문자, 기타 → '#'
선택 초성으로 칩 필터. 정렬은 초성 순서 → 영문.
```

## 11. 회사 엔티티 & 로고 파이프라인

> 원칙: **손으로 만드는 로고 DB ❌ / 자동 채워지는 “회사 엔티티 테이블” ⭕**

### 데이터 모델
로고는 코치별이 아니라 **회사 엔티티 단위**로 1개(같은 회사 코치끼리 공유).
```
Company {
  id            // 정규화된 엔티티 ID
  name          // 표준 회사명 (토스)
  aliases[]     // 비바리퍼블리카 · Toss · toss …
  domain        // toss.im  ← 로고 조회 키
  logoUrl       // 우리 CDN에 저장한 로고 (핫링크 X)
  brandColor    // 폴백 모노그램 배경색
  verified      // 관리자 검수 여부
}
// Coach.profile 은 companyId 로 참조
```

### 해석 파이프라인 (온보딩 시 1회)
```
코치가 회사명 입력
 → 회사 자동완성 (name → domain, 엔티티 정규화)
 → 도메인으로 로고 조회 (로고 API)
 → 로고 이미지 다운로드 → 우리 스토리지(S3/CDN)에 저장 (버전/해시)
 → 앱은 우리 CDN URL만 사용        ← 렌더 시 외부 핫링크 금지
 → 실패 시: 브랜드컬러 이니셜 모노그램 폴백 (현재 프로토타입 방식)
```
링크드인/이력서 임포트(AI 초안) 시 회사·도메인을 함께 추출하면 해석이 더 쉬움.

### 로고 소스 옵션
| 서비스 | 키 | 비고 |
|---|---|---|
| **logo.dev** | 도메인 | 무료 티어, 로고 전용 API — 1순위 추천 |
| **Brandfetch** | 도메인 | 브랜드 자산 CDN + API, 무료 로고 링크 |
| Clearbit Logo | 도메인 | `logo.clearbit.com/{domain}` — HubSpot 인수 후 지속성 불확실 |
| Google/DDG favicon | 도메인 | 16–64px 저품질 — 최후 폴백만 |

회사명→도메인 자동완성: Brandfetch/Clearbit autocomplete 또는 자체 사전.

### 시드 DB & 로고 해석 (인기 회사부터)
세상 모든 회사를 채우지 않는다. **인기 회사 상위 N개만 먼저** 채우면 수요 대부분을 커버(파워로우).
초기 시드: **`design/companies.json`** (대학생 선호 기업 ~30개 · id·name·aliases·domain·category·brandColor).

```js
// 로고 해석: domain → 로고 API → 우리 CDN 캐시 → 실패 시 모노그램
async function resolveLogo(company) {
  if (company.logoUrl) return company.logoUrl;                 // 이미 우리 CDN에 있음
  try {
    const src = `https://img.logo.dev/${company.domain}?format=png`; // 또는 Brandfetch
    const cdnUrl = await downloadAndCache(src, company.id);    // 우리 스토리지에 저장 (핫링크 X)
    return cdnUrl;
  } catch {
    return null;                                                // → 모노그램 폴백(brandColor+logoText)
  }
}
```
정규화: 검색·입력은 `aliases` 로 표준 회사 엔티티에 매핑(비바리퍼블리카→토스 등).

### 단계별 도입
- **Phase 0 (MVP·현재):** 이니셜 모노그램 폴백만. 로고 없이도 앱 동작. (`companies.json` 시드만 존재)
- **Phase 1:** 온보딩 때 logo.dev/Brandfetch로 해석 + 우리 CDN 저장. 상위 수백 개 회사만 커버해도 대부분 충족.
- **Phase 2:** 회사 엔티티 정규화 사전 + 관리자 로고 검수 + 코치의 로고 교체 요청.

### 주의
- **핫링크 금지**: 외부 로고를 렌더 시점에 직접 부르지 말 것(레이트리밋·ToS·CSP·안정성). 우리 CDN에 복제.
- **상표권**: 고용사 식별 목적의 명목적 사용(링크드인과 동일 성격)이나, **회사 후원/보증 오인 금지** + 로고 API ToS(상업 이용/출처표기) 준수.
- **폴백 필수**: 로고 없거나 동의 이슈 시 이니셜 모노그램. (프로토타입 `.logo` 뱃지가 이 폴백)
- **정규화 연동**: 회사명 정규화(§10)와 같은 엔티티 테이블을 공유.
