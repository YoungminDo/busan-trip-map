# 헬로마이미 Hello My Me — 텍스트 커피챗 UI 설계

> 디자이너 커뮤니케이션용 설계 문서 + 클릭형 시안
> **핵심 UX 원칙:** “학생은 **고민**으로 들어오고, **질문**으로 좁히고, **신뢰 지표**로 확신하고, **질문 티켓**으로 정중하게 연결된다.”

## 이 폴더 사용법

| 파일 | 내용 |
|---|---|
| **`hello-my-me-coffeechat.html`** | 브라우저에서 바로 열리는 클릭형 시안. 상단 탭으로 9개 화면 + 코치 카드 3종을 전환. 각 화면 옆 초록 주석이 **정보 우선순위와 노출 이유**를 설명. |
| **`README.md`** (이 문서) | A~J 구조의 설계 근거. 디자이너/기획자와 공유용. |

## A. 전체 UX 컨셉

**한 줄 정의:** 이름/얼굴이 아니라 **‘질문 적합도’로 연결되는** 텍스트 커리어 커피챗.

이 서비스는 “코치 쇼핑”도 “멘토 판매”도 아닙니다. 커리어 파트너는 *990원짜리 답변 노동자*가 아니라 *다음 세대가 자기다운 커리어를 찾도록 돕는 기여자*입니다. UI 전체가 이 포지셔닝을 지켜야 합니다.

**3개의 설계 기둥**

1. **고민 우선 인덱싱 (검색 < 인덱싱).** 학생은 자기가 검색할 직무명·용어를 모릅니다. 그래서 검색창이 아니라 “어떤 커리어 고민이 있나요?”라는 **질문 입력형 탐색**으로 진입시킵니다.
2. **질문 적합도 중심 카드.** 카드의 메인 타이틀은 사람 이름이 아니라 **역할(직무+회사유형+연차)**. 이름·얼굴은 하단의 작은 보조 정보.
3. **가격이 아니라 명분인 990원.** 990원은 몸값이 아니라 “현직자의 시간을 존중하며 정중하게 묻는 최소한의 명분.” 결제 화면은 ‘구매’가 아니라 ‘티켓 사용’으로 프레이밍.

**디자인 언어**
- 색: 성장·신뢰를 상징하는 **딥그린**(`#2C6B5B`) + 따뜻한 종이 배경(`#F6F5F1`). 질문 티켓에만 앰버(`#C9832B`)를 희소하게.
- 톤: 대학생에게 친근하지만 가볍지 않게. 사람을 점수화(별점·랭킹)하지 않음.
- 얼굴: 사진 대신 **이니셜 일러스트 아바타**(38px 이하)로 소개팅앱 인상 제거.

## B. 핵심 사용자 흐름

```
① 고민 인식      메인 헤드라인 “망설였던 질문 있나요?” → 자기 상태를 언어화
      ↓
② 질문/고민 진입  질문 입력형 탐색 or 고민·직무·상황 카테고리 (검색 아님)
      ↓
③ 파트너 탐색     코치 리스트(TYPE A) — 역할·질문 적합도로 비교
      ↓
④ 확신           코치 상세 — 잘 답하는 질문 / 어려운 질문 / 답변 샘플로 불안 해소
      ↓
⑤ 질문 작성       좋은 질문 가이드 3단계 + 상황 입력 → 질문 1개로 좁힘
      ↓
⑥ 정중한 연결     결제 = 질문 티켓 990원 (무응답 시 자동 복구)
      ↓
⑦ 안심 대기       접수→전달→작성→도착 타임라인 + 예상 응답시간
      ↓
⑧ 답변 소화       6블록 구조(요약·핵심·이유·할 것·주의·다음단계)
      ↓
⑨ 기여 기록       도움 평가(별점 비공개) + 강점 태그
      ↓
⑩ 리텐션 루프     다른 파트너 / 프로그램 / 커뮤니티 / FACE 진단으로 연결
```

핵심은 **③→④의 확신 구간**과 **⑥의 명분 전환**입니다. 여기서 학생의 심리 장벽(“이런 걸 물어봐도 될까”, “보답할 게 없는데 실례 아닐까”)이 풀립니다.

## C. 화면별 와이어프레임 설명

> 실제 렌더링은 `hello-my-me-coffeechat.html` 참조. 아래는 각 화면의 **정보 우선순위와 노출 이유** 요약.

### 1. 커피챗 메인
- **우선순위:** ① 공감형 헤드라인 → ② 질문 입력창(회전 placeholder) → ③ 고민→직무→상황 카테고리 → ④ 추천 파트너(TYPE A 축약) → ⑤ 인기 질문 → ⑥ 티켓 안내(하단).
- **이유:** ‘고민’을 최상단에 둬 용어를 모르는 학생도 진입. 티켓은 배너로 팔지 않고 맨 아래 ‘명분’ 카피로. 인기 질문은 “남들도 이런 걸 묻네 → 나도 물어도 되네” 안심 장치.
- **피한 것:** ‘인기 코치 1위’ 랭킹, 얼굴 그리드.

### 2. 고민 선택
- **우선순위:** 감정/상황 제목 → 한 줄 설명.
- **이유:** 직무명을 몰라도 “이게 내 얘기”로 클릭. 예) “직무가 궁금해요 — 마케팅, PM, 데이터… 실제로 무슨 일을 하는지 알고 싶다면.”

### 3. 코치 리스트 (표준 = TYPE A)
- **우선순위:** 역할 타이틀 → 산업 → 잘 답하는 질문 → 학생 태그 → 신뢰 지표 → (하단) 이름·배지.
- **필터:** 추천순 기본 / 회사유형 · 내 상황 · 질문 목적 · 응답 빠른순 · 도움 많은순. **‘인기순/랭킹’ 배제.**
- **이유:** 모든 카드가 동일 순서·동일 지표 위치 → 균일 스캔·공정 비교.

### 4. 코치 상세 (확신 화면)
- **우선순위:** 정체성 → **파트너 미션 문장** → 잘 답하는 질문 → **이런 질문은 어려워요(경계 명시)** → 추천 학생 → 답변 스타일 → 학생이 남긴 강점 → 도움 지표 → **답변 샘플** → 도움 후기 → CTA.
- **이유:** ‘어려운 질문’으로 기대치를 미리 정렬해 실망·환불을 막고, 답변 샘플로 결과물을 미리 체감시켜 결제 전 불안을 줄임.

### 5. 질문 작성
- **우선순위:** 좋은 질문 가이드(3단계, 입력창 위) → 질문 1개 입력 → 가벼운 상황 필드(학년·전공·관심직무·고민) → 답변 방식 태그 → 예시 문장.
- **이유:** 질문을 1개로 제한해 “너무 많이 물어 실례”라는 부담을 없애고, 상시 예시로 “이 정도면 되는구나” 안심.

### 6. 결제 (질문 티켓)
- **우선순위:** 초록 티켓(990원 + 명분 카피) → 보내는 질문·대상 재확인 → 안전장치 3종(무응답 복구·수정 가능·예상 시간) → CTA “질문 티켓 사용하기.”
- **이유:** 티켓 메타포로 ‘상담 구매’ 느낌 제거. 안전장치로 결제 리스크 체감 최소화.

### 7. 답변 대기
- **우선순위:** 접수 완료 → 접수·전달·작성·도착 타임라인 → 수정 가능 안내 → ‘둘러보기’.
- **이유:** ‘잘 전달됐다’는 확인 + 통제감. 대기 시간을 다른 탐색으로 전환.

### 8. 답변 수신
- **우선순위:** 파트너 정체성 → **질문 요약 / 핵심 답변 / 이유 / 지금 할 수 있는 것 / 주의할 점 / 추천 다음 단계** 6블록 → 후기 CTA → 이어보기(다른 파트너·프로그램·커뮤니티·FACE 진단).
- **이유:** 긴 답변도 구조로 소화. 코치도 이 틀에 맞춰 쓰면 품질이 균질화됨.

### 9. 도움 평가
- **우선순위:** “도움이 되었나요?” 3단 선택 → 강점 태그(복수) → 도움 후기 → 별점 비공개 안내.
- **이유:** 별점을 외부에 노출하지 않고 ‘도움됐어요 %·강점 태그·후기’ 중심 → 코치를 점수화하지 않음.

## D. 코치 카드 컴포넌트 제안 (3종)

정보 우선순위(공통): **① 직무+회사유형/산업+연차 → ② 잘 답하는 질문 → ③ 추천 학생 유형 → ④ 답변 스타일 → ⑤ 도움 지표 → ⑥ 응답시간 → ⑦ 질문 수 → ⑧ 파트너 배지 → ⑨ 이름(하단 작게) → ⑩ 얼굴(선택적 이니셜)**

### TYPE A · 역할 중심형 ⭐️(리스트 표준)
- **구조:** 역할 타이틀 → 산업 → 잘 답하는 질문 → 학생 태그 → 답변 스타일 → 지표 → (하단) 이름·배지.
- **장점:** 3초 스캔, 직무 매칭 직관적, 카드 간 비교 균일.
- **단점:** 완전 초심자에겐 용어 장벽, ‘나에게 맞는가’보다 ‘무슨 직무인가’가 앞섬.
- **적합:** 직무별 리스트, 추천 캐러셀 등 다수 비교 맥락.

### TYPE B · 질문 중심형
- **구조:** 학생의 질문(공감 후킹) → “이 질문에 잘 답하는 파트너” → 역할 → 태그 → 지표 → 이름.
- **장점:** “이건 내 얘긴데?” 공감으로 심리 장벽 최대 완화, 직무명 몰라도 진입(인덱싱 철학과 정합).
- **단점:** 질문 1개에 묶여 넓은 역량이 안 보임, 리스트 다수 노출 시 질문끼리 경쟁, 1인 중복 노출 위험.
- **적합:** 메인 ‘인기 질문 → 파트너’ 추천, 검색/고민 선택 결과 최상단.

### TYPE C · 추천 학생 중심형
- **구조:** “이런 학생에게 추천” + 학생 상황 문장 → 역할 → 잘 답하는 질문 → 태그 → 지표 → 이름.
- **장점:** “나 같은 사람도 물어도 되는구나” 안정감 최상, 비전공·무스펙 등 불안한 학생 포용.
- **단점:** 추천 대상 아닌 학생의 배제감, 역할 정보가 뒤로 밀려 스캔 저하, 과한 라벨링 시 편가르기 인상.
- **적합:** ‘내 상황으로 찾기’ 결과, 온보딩 직후 맞춤 추천.

### 최종 추천 — “A를 기본, B·C는 문맥 카드로”
> **하나를 고르지 말고, 같은 데이터로 3가지 얼굴을 문맥에 맞게 렌더링하세요.**
- **리스트 표준 = TYPE A** (비교 스캔·코치 품격에 최적)
- **메인 인기 질문 / 검색 결과 상단 = TYPE B** (공감 후킹)
- **‘내 상황으로 찾기’ 결과 상단 = TYPE C** (안정감)

이렇게 하면 코치 데이터 모델은 하나로 유지하면서, 진입 맥락에 따라 학생이 가장 자연스럽게 반응하는 카드를 보여줄 수 있습니다.

## E. 필터 / 검색 / 추천 구조

**검색 철학: 검색창 < 질문 입력형 탐색.**
- placeholder 회전: “어떤 커리어 고민이 있나요?” / “예: 비전공자인데 데이터 분석가가 될 수 있을까요?” / “예: 스타트업 첫 커리어, 괜찮을까요?” / “예: 브랜드 마케터는 실제로 무슨 일을 하나요?”

**5개 인덱스 축(학생의 언어로):**
1. **고민으로** — 직무 궁금 / 회사 선택 / 준비 방법 / 상황 불안 / 진로 막막 / 현실 이야기
2. **직무로** — 마케팅·브랜드 / 데이터·AI / UX·UI / PM·기획 / BD·사업개발 / 영업 / 콘텐츠·미디어 / HR / 금융·전략·컨설팅 / 문화예술 / 창업
3. **회사 유형으로** — 대기업 / 스타트업 / 외국계 / 중견 / 에이전시 / 플랫폼 / B2B / 공공·비영리 / 프리랜서
4. **내 상황으로** — 비전공 / 문과 / 예체능 / 인턴 무경험 / 무스펙 / 지방대 / 휴학·유예 고민 / 진로 전환 / 첫 커리어
5. **질문 목적으로** — 직무 이해 / 준비 방법 / 포트폴리오 / 면접·자소서 / 회사 선택 / 산업 이해 / 커리어 방향 / 현실 조언

**정렬:** 추천순(기본) · 응답 빠른순 · 도움 많은순.
**추천 로직 표시 원칙:** ‘인기순 1위’ 같은 랭킹 카피 금지. “당신의 고민 #비전공 과 잘 맞아요”처럼 **매칭 근거**로 노출.

## F. 주요 UX 카피 (화면별)

**메인 헤드라인**
- “현직자에게 묻고 싶었지만 망설였던 질문 있나요?”
- “검증된 커리어 파트너가 현장의 언어로 답해드려요.”

**티켓/명분**
- “질문 티켓 1장 · 990원”
- “현직자의 시간을 존중하며, 정중하게 질문을 남길 수 있어요.”
- “무료 DM은 학생도 망설여지고, 현직자도 답하기 어렵습니다. 헬로마이미는 부담 없이 묻고 정중하게 답하는 구조를 만듭니다.”

**CTA (권장)**
- “질문 티켓으로 물어보기” / “이 파트너에게 질문하기” / “990원으로 정중하게 질문 남기기” / “질문 티켓 사용하기”

**절대 금지 문구**
- ~~구매하기~~ · ~~판매 중~~ · ~~990원 상담~~ · ~~저렴한 멘토링~~ · ~~인기 코치 1위~~

**질문 작성 가이드**
1. 내 상황을 짧게 알려주세요. 2. 궁금한 걸 한 가지로 좁혀주세요. 3. 원하는 답변 방향을 말해주세요.
- 예시: “3학년 문과생이고 데이터 분석에 관심 있어요. 코딩 경험은 거의 없는데 이번 방학에 무엇부터 준비하면 좋을까요?”

**파트너 미션 문장**
- “현장에서 겪은 진짜 이야기를 나눠, 다음 세대가 더 나은 커리어 선택을 할 수 있도록 돕고 있어요.”

## G. 리뷰 / 도움 평가 시스템

**원칙: 별점은 내부용, 외부는 ‘도움’ 언어.**
- 평가 질문: “답변이 도움이 되었나요?” → 매우 도움 / 도움 / 기대와 달랐어요(완곡한 부정).
- 강점 태그: 현실적 · 구체적 · 따뜻함 · 이해하기 쉬움 · 방향 정리됨 · 준비 방법을 알게 됨 · 빠름 · 다시 질문하고 싶음.
- **외부 노출:** 도움됐어요 96% · 질문 42개 · 평균 18시간 · 학생이 남긴 강점 #현실적인조언 #구체적인답변 · 도움 후기 1~3개.
- **별점·순위는 외부 비공개.**

## H. 코치 명예 설계

- **역할이 이름 위에.** 카드/상세의 메인 타이틀은 직무·연차. 이름·얼굴은 보조.
- **미션 문장으로 프레이밍.** ‘답변 노동자’가 아니라 ‘기여자’. 상세 상단에 미션 배치.
- **경계 명시로 존중.** “이런 질문은 어려워요”로 대외비·합격보장 요구를 사전 차단.
- **평가 보호 규칙(운영):**
  - 인신공격성 후기 비노출
  - ‘회사 내부정보를 안 알려줬다’는 이유의 부정평가 미반영
  - 질문 범위를 벗어난 불만은 운영팀 검토 후 처리
  - 공개 후기는 다른 학생에게 도움되는 내용 중심으로만 노출
- **속도 경쟁 지양.** 응답시간은 안내하되 ‘가장 빠른 1위’식 강조 금지.

## I. MVP 우선순위

### 🟢 MVP (반드시)
- 메인(질문 입력형 탐색 + 고민·직무 카테고리)
- 코치 리스트 (**TYPE A 카드**) + 기본 필터(고민·직무·회사유형)
- 코치 상세 (미션·잘 답하는 질문·어려운 질문·지표·CTA)
- 질문 작성 (가이드 3단계 + 질문 1개 + 상황 입력)
- 결제 = 질문 티켓 990원 + **무응답 자동 복구**
- 답변 대기(타임라인) / 답변 수신(6블록)
- 도움 평가(3단 선택 + 강점 태그, 별점 내부 저장)
- 도움 지표(도움됐어요 % · 질문 수 · 평균 응답시간)

### 🟡 Phase 2 (고도화)
- TYPE B/C 문맥 카드 동적 렌더링
- ‘내 상황으로 찾기’ · ‘질문 목적으로 찾기’ 축
- 추천 로직(매칭 근거 표시), 온보딩 맞춤 추천
- 답변 샘플 라이브러리, 후기 큐레이션
- 리텐션 루프(프로그램·커뮤니티·FACE 진단 연결)
- 파트너 대시보드(질문 관리·기여 기록)

## J. 리스크와 개선 제안

| 리스크 | 왜 위험한가 | 개선 |
|---|---|---|
| **소개팅앱화** | 얼굴/호감으로 코치 선택 | 사진 대신 이니셜 아바타, 이름·얼굴 하단 보조, 메인 타이틀=역할 |
| **배달앱화** | 응답속도·가격 경쟁 | ‘가장 빠른 1위’ 금지, 응답시간은 안내 수준, 티켓=명분 카피 |
| **멘토판매 플랫폼화** | 구매/랭킹/인기순위 | ‘구매·상담·1위’ 문구 금지, 정렬에서 인기순 제외, 매칭 근거로 추천 |
| **990원의 저가 인식** | ‘싼 상담’으로 격하 | 몸값이 아닌 ‘정중한 명분’ 프레이밍, 티켓 메타포, 무응답 복구 |
| **초심자 용어 장벽** | 직무명 몰라 이탈 | 고민·상황 우선 인덱싱, 질문 입력형 탐색, TYPE B/C 진입 카드 |
| **결제 전 불안** | “답 안 오면?” | 무응답 자동 복구, 예상 응답시간, 답변 샘플·어려운 질문 사전 고지 |
| **부당 평가로 코치 명예 훼손** | 범위 밖 불만·인신공격 | 별점 비공개, 보호 규칙 운영, 후기 큐레이션 |
| **추천 학생형(C)의 배제감** | “난 대상 아닌가?” | C는 ‘내 상황’ 결과에서만, 라벨링 최소화, 기본은 A |

**우선 검증할 가설:** ‘역할 중심 카드(A)’가 ‘얼굴 중심’보다 실제 질문 전환율이 높은가 — MVP에서 A 단독으로 검증 후, B/C를 진입 지점에 A/B 테스트로 추가 권장.
